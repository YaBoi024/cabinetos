# Packages CabinetOS actually cares about in the Bazzite base, in AREAS, and
# what to check on the A9 when an area changes.
#
# Used by ci/check-base-update.sh (through ci/base-report.py) to decide whether
# a Bazzite update is RELEVANT (a human should look at it before merging) or
# ROUTINE (it is almost certainly fine and can be merged on the strength of a
# green build), and to write the pull request's update notes and its checks.
#
# Bazzite rebuilds daily. Most of those rebuilds move packages CabinetOS has no
# opinion about — desktop applications, fonts, translations, Windows
# compatibility. Without this filter, base bumps become a stream of noise and
# stop being read, which is worse than not having them at all.
#
# THE LINES (2026-10-09):
#
#   area: <name>      starts an area; the patterns below it belong to it. The
#                     name is what the update notes and the checks say, so it
#                     is written for a player, not for us.
#   <glob>            a package: one shell glob per line, matched against the
#                     package NAME only. A package's Terra build (terra-<name>)
#                     matches its name's pattern too: Terra's WirePlumber
#                     replaced Fedora's in 44.20260929, and the old list called
#                     that "WirePlumber removed" and never showed the new one.
#   log: <check> :: <command>
#                     a check the A9's log answers, once it runs the testing
#                     image. tools/base-checks.sh runs the command there in
#                     bash as `cabinet`, no sudo; exit 0 is a pass, and what
#                     it prints is shown on a fail.
#   tv: <check>       a check that needs MMagTech's eyes or hands.
#   changelog: <part> :: <regex>
#                     which kernel changelog lines (kernel.org's, and the OGC
#                     kernel's own patches) are about a part the console uses.
#                     Python regex, matched against each commit's subject.
#   series: <part> :: <path> ...
#                     on a jump to a new kernel series (7.2 to 7.3), list
#                     every change the series made to these files, from
#                     torvalds/linux. The stable changelogs carry fixes only,
#                     and new hardware (a new controller) arrives in a series.
#   changelog-skip: <regex>
#                     a changelog line that matched a part but is not news for
#                     this console: another chip in the same driver, or a
#                     clean-up that fixes nothing. Any one matching drops it.
#   kind: stripped    the area's packages are ones CabinetOS removes, so a new
#                     version of one is not news; only a name appearing or
#                     going is.
#
# Only the areas an update changed get checks, and a check several of them
# ask for is listed once (MMagTech, 2026-10-09: "each time we do a base
# update, I can't sit here and troubleshoot the whole OS"). So write the same
# check with the same words wherever it appears. Keep the tv: lines few: a
# kernel or Mesa change gets a short broad check, not the whole OS.
#
# ---------------------------------------------------------------------------
# ADD TO THIS FILE AS THE PROJECT GROWS.
# Phase 3 added the frontend's runtime libraries and fonts. Phase 5 added the
# cores' own, on the day the image started carrying them. A package CabinetOS
# relies on that is not listed here can break silently in a base bump that
# looked routine.
# ---------------------------------------------------------------------------

# --- System update ----------------------------------------------------------
# bootc and ostree were under Kernel and startup until 2026-10-21. The
# console's update (system_files/usr/libexec/cabinetos-update) reads bootc's
# own output: `bootc status --json` (the booted image, a staged version),
# the text of `bootc upgrade --check` ("No changes in", "Version:") and its
# progress lines (ProgressBytes "pulling", ProgressSteps). None of that is a
# promise bootc makes, and a change shows only as a wrong answer in Settings,
# System update. The size it offers comes from skopeo and jq and from
# ostree's names for the layers a console holds (sha256_3A_...), which the
# log check below runs as the update does. bootc answers only root, so its
# own output is the TV check.
area: System update
log: The A9 booted the image's own kernel :: [ "$(uname -r)" = "$(rpm -q --qf '%{VERSION}-%{RELEASE}.%{ARCH}' kernel-core)" ]
log: No service failed to start :: out=$(systemctl --failed --no-legend --plain); [ -z "$out" ] || { echo "$out"; exit 1; }
log: The update check still finds every layer of the running image on the console :: r=$(rpm-ostree status --json | jq -r '.deployments[] | select(.booted) | (."container-image-reference" | sub(".*docker://"; "") | sub(":[^:/]*$"; "")) + "@" + ."container-image-reference-digest"'); m=$(skopeo inspect --raw "docker://$r") || { echo "skopeo could not read $r"; exit 1; }; if jq -e .manifests >/dev/null <<<"$m"; then m=$(skopeo inspect --raw "docker://${r%@*}@$(jq -r 'first(.manifests[] | select(.platform.architecture == "amd64") | .digest)' <<<"$m")") || exit 1; fi; n=$(ostree refs --repo=/sysroot/ostree/repo ostree/container/blob | jq -R -s --argjson m "$m" '(split("\n") | map(select(length > 0))) as $have | [$m.layers[] | select((.digest | sub(":"; "_3A_")) as $d | $have | index($d) | not)] | length'); [ "$n" = 0 ] || { echo "layers of $r the update would fetch again: ${n:-none counted}"; exit 1; }

# --- Graphics --------------------------------------------------------------
# Phase 2 runs the frontend inside gamescope and Phase 5 runs emulators inside
# it. A gamescope or Mesa regression is a project-stopping event.
#
# `vulkan-*` and `mesa-*` became load-bearing for the PRODUCT on 2026-09-20,
# not just for gamescope: PlayStation 2 and GameCube render through Vulkan and
# the frontend dlopens libvulkan.so.1 itself. Losing the loader or the RADV
# driver takes those two systems out while every other core keeps working, so
# it is the quiet kind of breakage. build_files/build.sh asserts both, because
# a dlopen is invisible to `ldd` and therefore to require-frontend-libs.sh.
#
# Mesa also encodes Remote Play's stream (VA-API), and draws Steam's games.
#
# gamescope has an area of its own since 2026-10-21, with every Graphics
# check and two of its own: the console leans on gamescope's internals, and
# a Mesa update need not ask for them. The pause menu over a game run as a
# program or a PS2 game is a window of ours that gamescope must put on top
# and give the pad to (frontend/src/overlaywin.cpp: the STEAM_OVERLAY,
# STEAM_INPUT_FOCUS and GAMESCOPE_NO_FOCUS properties, read by gamescope's
# own code, not a promise it makes; tools/gamescope-overlay-test.sh tries it
# by hand).
area: The picture on the TV (gamescope)
