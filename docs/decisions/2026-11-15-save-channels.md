# Saves and states live in RomM's save channels

- **Decided:** The console keeps every save and state in RomM's save channels, the way RomM and the other apps that use them do, and builds no import or converter of its own. RomM converts other apps' saves; Switch is the one exception, converted on the console with a pinned Sigil ([romm-converts-saves](2026-11-20-romm-converts-saves.md)). It moves to channels fully and keeps no old way. By area:
  - **Which save a game starts from.** The newest save RomM holds for the person, made on any device or app, in any channel or from before channels. Newest means when it was made, not when it reached RomM. Nothing is asked and there is no screen to pick a save (2026-10-11). A save the console has not sent yet wins over anything on RomM. A save of the console's own that RomM kept beside a newer one is never replaced by one made before it. Before another device's save replaces the console's own on its drive, one copy is kept aside, one per person and game (2026-11-17).
  - **Where the TV saves.** Into the channel it continued from, which for the TV's own progress is RomM's "default", where every other app looks (2026-11-15, 2026-11-17). The save goes up once, after the game has closed, as one snapshot with the game's states. When another device saved meanwhile, RomM keeps both and the one made later goes on top: made later is when the console wrote its save against when RomM took the other device's. When the TV starts from its own save because it can't use the newest, its progress stays beside the newest in the same channel, kept by RomM (2026-11-17). A hardcore channel from another app is never saved into: the TV's progress goes into a channel of its own named "softcore", RomM's own word (2026-11-15, named 2026-11-17).
  - **What the TV says.** "Continuing from another device" when the save was made anywhere but this TV, and "Couldn't use the newest save" when the newest can't be used. After a reinstall the first shows only when RomM says another app's device made the save and no console holds it: a missed message is accepted, a wrong one is not (2026-11-17). The TV shows no list of channels: going back to an older save, or to another channel, is "Restore as current" on RomM's website, and the TV follows the newest (2026-11-15).
  - **States.** A state goes inside the game's snapshot and goes up with the save when the game is left; the pill says "State saved" (2026-11-15). The TV's states sit in slots 1, 2 and 3, newest first, and the TV shows the three newest of its own wherever they are on RomM, as RomM's web player does; where RomM's list leaves out a state's hash, the console reads the channel's history for it rather than leave the state out (2026-11-19). States from before the update stay offered and go into the game's first snapshot (2026-11-17). States never cross between apps.
  - **Nothing is deleted on RomM.** The console deletes no save and no state there; RomM's own settings decide how much history it keeps (2026-11-17).
  - **Saves from before the update** move into a channel game by game, the first time each game is started after the update, by RomM copying the old save in. The old save stays as it was, so a console not yet updated goes on using it (2026-11-15).
  - **Saves from other apps.** A save the console made comes back exactly as stored. Another app's newest is asked of RomM in the console's form and checked (its size, its format's marks, a save inside) before it is used; one that fails leaves the game on the console's own (2026-10-11). Every save the console sends keeps today's tag and names its core in Sigil's spelling beside it, so the same core in another app gets the same bytes (2026-11-17). Dreamcast keeps one memory card per game. DS, Game Boy Advance and the Mega Drive family take another app's save only when the same emulator made it, until RomM converts them (2026-11-17). Conversion, arcade games and saves outside channels have files of their own: [romm-converts-saves](2026-11-20-romm-converts-saves.md), [arcade-saves-cabinetos-only](2026-11-20-arcade-saves-cabinetos-only.md), [other-apps-saves-outside-channels](2026-11-20-other-apps-saves-outside-channels.md).
  - **One RomM device for every console,** `cabinetos`, as before: no pairing again and no naming screen. The console keeps its own note of the snapshot it last had (2026-11-15).
  - **Offline and an older RomM.** Offline plays from the saves as last seen, as before. On a RomM too old for channels the console neither reads nor writes saves or states, plays from what it last saw, and sends what waited by itself within a minute of the server gaining channels (2026-11-15, 2026-11-20). Which RomM the console needs: [romm-version-needed](2026-11-17-romm-version-needed.md).
  - **A crash or a power cut mid-game.** A save the game had already written is kept and sent at the next start; one that fails the save check is not kept. Every file the console replaces is on the drive, its name included, before the console goes on (2026-11-20).
  - **A sitting where nothing was saved** still sends a snapshot when the game itself changed its save (a board's counters, a record), as before channels: the console sends only bytes that changed and can't tell a game's own write from a save (2026-11-20).
  - **The save's own picture** is taken about a second after the game's save stops changing and goes up with it, as RomM's web player does. A system whose emulator writes the save only as the game closes gets none (2026-11-19).
  - **Cartridge clocks and Saturn's backup cartridge** travel with the save (2026-10-12). Arcade's extra files wait for an arcade form in RomM (2026-11-15).
- **Date:** 2026-11-15, the ten decisions for the switch; with those of 2026-10-11 and 2026-10-12, the answers of 2026-11-17, and the choices made while building, 2026-11-18 to 2026-11-20.
- **Why:** RomM is the source of truth and owns management ([romm-owns-management](2026-10-21-romm-owns-management.md)), so the console follows it and stays in line with the other apps, rather than guessing their names and tags or keeping converters the server already has. Channels stop two devices overwriting each other, so a console back from a trip can't put older progress over newer, and the other save is never lost: it stays on RomM. Where a rule had to choose, it keeps the player's progress. One push when the game is left, not one per state, because each push is a snapshot and a channel keeps ten. One shared device means no pairing again, at the cost of RomM's history not telling consoles apart.
