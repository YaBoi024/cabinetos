# Running from a USB drive: the PC left alone, the drive filled, the zone asked

- **Decided:** A console whose system is on a drive that can be unplugged (a portable install, the disk image written to a USB drive) treats the PC it runs on as somebody else's. (1) Every drive of that PC that cannot be unplugged is ignored by udisks, from the udev rule that already hides the console's own drive (`cabinetos-system-disk`), so the console never mounts, lists or formats it and Steam never sees it; other USB drives work as on any console. (2) At every start, `cabinetos-grow-root.service` grows the system's partition and filesystem into free space directly after it, and does nothing on a console whose system is on the PC's own drive. (3) First run's first screen asks the time zone, region then city, only when no zone is set. (4) A console no installer ran on keeps the PC's hardware clock in local time, as Windows does: the image's `/etc/adjtime` says LOCAL, the zone is set without writing that clock, and chrony, which keeps it, starts only on a start that began with a zone.
- **Date:** 2026-11-03
- **Why:** MMagTech chose the portable install (2026-11-02) so that CabinetOS never chooses a drive on a tester's PC; that holds only if it never touches one either. One udev rule, not a check in each place, because udisks's ignore is already what the console's drive code, Steam's Storage page and the Steam library script go by, so one decision covers all of them and the ISO install's path is the same code with nothing new to hide. Growing comes from our own small script because systemd-repart picks partitions by type, and an ISO install's are the same "Linux data" type, and bootc's own grower is not in Bazzite. The zone screen and its rules were agreed with MMagTech on 2026-11-03. The clock: a Windows PC keeps its clock in local time, and a console that wrote UTC into it would move the time Windows shows by hours after every session. The kernel writes that clock in local time only when a start began with a zone that is not UTC, which a portable's first start never has, so on that start nothing writes it; `timedatectl set-timezone` would write it from a system clock that is hours off at that moment.
- **Numbers:** #649, "Portable install, step 2: running from a USB drive (PC's drives hidden, drive filled, time zone asked)"; agreed with MMagTech on 2026-11-02 and 2026-11-03 as step 2 of the portable install plan.
- **Replaces:** none. An install from the ISO keeps its installer's zone and clock setting, and every console behaves as before when its system is on the PC's own drive.
