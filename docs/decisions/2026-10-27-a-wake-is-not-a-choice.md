# A wake is not a choice

- **Decided:** whatever wakes the console, the presses that come with it do nothing in a menu. A press on a dimmed screen only lights it, as before. After the screen comes back from off, after the machine comes back from Sleep, and after a device starts streaming, every press does nothing in a menu for 3 seconds (`idle::kWakeSettleSeconds`). A game in play hears every press, as before, and the power key keeps its own rule: after the screen was off it opens the Power menu, after Sleep it is ignored.
- **Date:** 2026-10-27
- **Why:** a press that comes with a wake lands on a focus nobody has seen yet: on the A9 a game started 0.8 s after a press lit a screen that was off, and streams connecting started the game Home had focused. What sends the stream's presses is not known, so the console refuses them whatever sends them. One wait for every wake is one rule; it costs only a press nobody could aim. 3 seconds is the build session's starting value, for MMagTech to judge on the TV. Weighed and not taken: fixing only the stream (a child pressing A on a dark screen would still start a game unseen), swallowing only the first press of a stream (the first report had two, 0.2 s apart), waiting on Moonlight (nothing found saying it sends a press).
- **Numbers:** #411, "Connecting Moonlight can start the game Home has focused"; PR #599, "A wake is not a choice: no press acts in a menu for 3 s after a wake (#411)"; #294, "A stream started while the screen is asleep stays black", whose stream counting as somebody arriving stays.
- **Replaces:** none.
