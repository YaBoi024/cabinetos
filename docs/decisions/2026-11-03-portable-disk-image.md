# The portable disk image: one .img.xz, cut to size, booted by CI

- **Decided:** `build-disk.yml`'s `portable` type makes `cabinetos-portable.img.xz`, the one file a tester writes to a USB drive with Etcher or Rufus. It is the builder's raw disk changed afterwards (`ci/make-portable-image.sh`) in four ways: cut to what it holds, with the ISO install's `rhgb quiet` in place of the builder's serial console, with a first start's writes done beforehand or delayed (`2026-11-04-portable-first-start.md`), without shim's fallback file, so it adds no entry to the PC's boot list, and with the key screen for a PC with Secure Boot on (`2026-11-04-portable-secure-boot.md`). Compressed with `xz -6`, CRC32. The run fails unless `ci/check-portable-boots.sh` boots that file in a VM to first run's time zone screen. Publishing is not part of this type.
- **Date:** 2026-11-03
- **Why:** The builder cannot be told a smaller size: it takes twice the image's, 28.9 GB, and a tester's tool writes every byte of a compressed file, free space too. So the filesystem is packed and cut afterwards, the same way the ISO is repacked afterwards (`2026-11-02-installer-iso-repacked.md`), and the builder stays pinned. The formats both tools open are `.xz`, `.gz`, `.bz2` and `.zip`, by their own source (Etcher's `supported-formats.ts` has no `.zst`; Rufus's `vhd.c`); `.xz` is the smallest of them. `-6` because `-9` saved 2.4% for 11 minutes more on the runner; CRC32 because Rufus's decoder checks only that one. The serial console left the TV on a kernel line for the minutes of a first start, where an ISO install shows its splash. Shim's fallback wrote an entry for itself into the VM's firmware on the first boot, and a portable treats the PC as somebody else's (`2026-11-03-running-from-a-usb-drive.md`). Shim still stores its own `SbatLevel` variable, as it does from any Linux USB drive. Not the alternative of leaving the fallback and removing its entry at each start, which would write to the PC's firmware to undo a write. Kept as it is: a later shim update makes bootupd write the fallback back on a drive already written, so that drive adds one entry on its next start; those updates are rare, and stopping them would change the image every console runs. The boot check runs under KVM because GitHub's runner has it, and fails rather than falling back to emulation without it.
- **Numbers:** PR #653, "Portable install, step 3: the disk image and its boot check"; agreed with MMagTech on 2026-11-03 as step 3 of the portable install plan.
- **Replaces:** none.
