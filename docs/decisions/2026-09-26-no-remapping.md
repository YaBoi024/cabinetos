# No remapping, except an arcade game's Controls

- **Decided:** No button remapping, for the first release at least: every system plays with RetroArch's out-of-the-box layout, read by position (the bottom face button is RetroPad B, and so on). Since 2026-10-25 arcade games are the one exception, through their pause menu's Controls ([arcade-controls](2026-10-25-arcade-controls.md)). A fixed change the console makes for everyone is not a remap: on the DS and 3DS, L3 shows the screens and the DS's lid is on R2 ([ds-3ds-screen-view](2026-10-26-ds-3ds-screen-view.md)).
- **Date:** 2026-09-26
- **Why:** MMagTech asked whether Button mapping should be RetroArch-style remapping, then whether he was drifting into adding too much: *"the os is meant to be simple and take the complexity away alot of emulators add."* The defaults by position are the ones people know. With four players a remap has no clean owner: per system changes the game for everyone, per pad multiplies screens, per person fails for players 2 to 4. If it is asked for after release, the likely request is "A and B swapped on a Nintendo-style pad", which is one switch.
- **Numbers:** docs/PROJECT.md, "No mapping screen, and the in-game shortcuts' shape" (2026-09-26), its first point. No issue.
- **Replaces:** none.
