# RPCS3's per-game settings ride in the image as a snapshot

- **Decided:** The image carries a snapshot of the RPCS3 team's per-game settings database, `build_files/rpcs3-config-database.json` (about 300 KB, 2,294 games), which `build_files/install-rpcs3.sh` puts beside RPCS3 and the console copies into RPCS3's config folder before every PlayStation 3 game starts, so every game gets the entry a plain RPCS3 install gives it. `tools/fetch-rpcs3-config-database.py` refreshes it on a computer, never the console, with each move of RPCS3's pin and with the monthly base update, as a diff a reader can see; the pull request says how many of its entries the pinned build rejects.
- **Date:** 2026-11-06
- **Why:** RPCS3 lays a game's entry over its global settings at every boot, `--no-gui` included, but only its own window downloads the file, from `https://api.rpcs3.net/config/?api=v1`, and the console starts RPCS3 without one, so no PlayStation 3 game got its entry (found 2026-11-06 while chasing red in Unreal Engine 3 games; Lollipop Chainsaw's entry is Write Color Buffers). A snapshot over fetching at image build time: the server offers no version to pin, so a build would lean on a third-party server being up and would ship whatever it served that day, unread; committed, the file changes only in a pull request, where its diff is read. Over the console fetching it: the console connects only to RomM and GitHub (CONTRIBUTING.md, "The rules"). The snapshot is taken against the pinned build: an entry naming a setting the build does not have is rejected by RPCS3 itself when it reads the file, whole, so the count in the pull request says what that build loses (39 of 2,294 on 2026-11-06, every one naming a drive read-speed setting newer than the build).
- **Numbers:** PR #665, "PS3: the RPCS3 team's settings for each game, from a snapshot in the image"; PR #664, "PS3: filtering as the game asked, and small buffers unscaled", where it was found.
- **Replaces:** none.
