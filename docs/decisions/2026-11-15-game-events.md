# Game events go to one app at home, which does the rest

- **Decided:** The console sends what is happening in a game (started, paused, resumed, ended, an achievement, a set completed, and a test) as JSON to one address the owner types in Settings, System, Game events, and that app (n8n, Home Assistant, Node-RED) decides what happens next: lights, Discord, a phone. The address is the switch, console-wide and off to start; it must be a private, local or Tailscale address, checked every time it sends, after a knock with the test message on every network the console joins. No Discord built in, no switch per message, no QR code. A LinkUp friend's console sends its own started and ended to its own address; nothing about one console's setup crosses LinkUp.
- **Date:** 2026-11-15
- **Why:** A post to Discord is a notification like a text, which needs nothing from the console. What only the console can do is say what is happening in the game, so the room can react to it, and that needs one message to an app at home. Each Discord, Telegram or Home Assistant feature built in would be the console managing a service the owner already has an app for. Switches per message would be settings for the few: the app picks what it uses. A QR code would need a web page on the console, and nothing about this needs the console to listen. Home addresses only, and the knock, keep a friend's network from hearing anything, since a private address exists on every network.
- **Numbers:** issue #716, "Game events: tell an app at home what is happening in a game", settled with MMagTech on 2026-11-15; the pull request that builds it, "Game events: tell an app at home what is happening in a game (#716)".
