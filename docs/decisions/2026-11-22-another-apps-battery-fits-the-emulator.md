# Another app's battery save fits the emulator's, not matches it

- **Decided:** Another app's battery save is used when it is no longer than the battery the console's emulator holds as the game starts. A shorter one goes in with the rest left blank, as RetroArch puts a save in and as the console puts in its own. A longer one is refused, and the game starts from the console's own save as before.
- **Date:** 2026-11-22
- **Why:** An emulator's battery as a game starts is the most it reads, not always the game's size. mGBA holds 128 KiB until the game first touches its save chip, and Genesis Plus GX holds 64 KiB until the first frame (Mega Drive, Master System, Game Gear); both write less, the chip's size or the battery trimmed of its last blank bytes, and both start it blank. Sigil's pages for both at RomM's pin say the same bytes in any length are the same save. Asking for the emulator's size exactly refused every Game Boy Advance save but a 128 KiB chip's, and most Mega Drive family saves, even from the same emulator in another app (the first player report, on Discussion #731). Not taken: any length, cut to the emulator's as RetroArch does, since a longer file loses its end and nothing in it says the end is only padding; a rule per emulator, since one rule covers every system. The one longer save seen is desktop mGBA's, a game with a clock chip carrying 16 bytes of clock at its end (Pokémon Ruby, Sapphire, Emerald): it waits for RomM, whose Sigil converts it once RomM pins a Sigil from 2026-11-19 or later (argosy-sigil#24, Sigil 4980f69), rather than the console cutting it (MMagTech, 2026-11-22).
- **Numbers:** #346 "Move saves to RomM's save channels (Sigil)"; Discussion #731 "Save channels: known gaps".
- **Replaces:** none. It says how the size check in [save-channels](2026-11-15-save-channels.md) ("its size, its format's marks, a save inside") reads a battery.
