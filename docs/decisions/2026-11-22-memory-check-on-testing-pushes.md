# The self-tests run under AddressSanitizer on each push to testing

- **Decided:** On each push to `testing` that changes the frontend, CI builds the frontend a second time with AddressSanitizer and runs every self-test on that build, in a workflow of its own beside the image build. A failure stops neither the image nor its promotion; it is read before the merge. It does not run on pull requests. The runtime library it needs is added to a copy of the builder in that job, not to the builder's recipe.
- **Date:** 2026-11-22
- **Why:** The save code reads files other apps made, in every size and layout, and changes with each new system and each RomM release; a wrong length there can pass a test and still put the wrong bytes in a player's save. AddressSanitizer stops a test at the first such byte. Every change reaches `testing` before `main`, so a check there covers everything that ships. Measured on the reference console: the build takes 124 s with it against 34 s without, and the tests 53 s against 51 s; on a pull request that would be several more minutes of waiting each time, and beside a testing image build, which ran 10.6 to 17.8 minutes in the eight before this, it is none. The first run, by hand on 2026-11-22, found nothing. The builder's recipe is part of every core's cache key, so a change to it would build every core again. Not taken: every pull request (the wait), and no job at all (a mistake in the save code would then reach players unseen).

- **Replaces:** none.
