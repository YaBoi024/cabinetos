# A token the console is done with is owed a revoke on the disk

- **Decided:** A token the console is done with (the one a re-pairing replaces, a removed person's) goes on a list on the console, `revoke.json`, before its login changes, and revokes itself on RomM once nothing in the program uses it. It stays on the list through a power cut, a server that is away and the end of the program, and the next start sends it; any answer RomM gives, a refusal included, settles it. Sign out gives each token one try and three seconds in all, and its list goes with everything else.
- **Date:** 2026-11-22
- **Why:** revoking at once, as the first draft did, left a token live on RomM for good whenever the power went or the server blinked at that moment, which is the fault itself; and it could cancel a token an upload or a download was still using, which RomM answers with 401, the console's sign of another server. Leaving every revoke to the next start would have been simpler, but a console can stay on for weeks. What it costs: after a Remove with the server away, that person's token stays on the console, private as a login is, until RomM answers; dropping it there would leave it live on RomM with nothing to revoke it by. Sign out leaves nothing behind on the console, so it keeps no list and a server away then keeps the tokens.
- **Numbers:** #545, "Revoke the console's RomM token on re-pair, Remove account and Sign out (waiting on RomM)"; PR #528, "Revoke the console's RomM token on re-pair, Remove account and Sign out (#545; waiting on RomM)".
- **Replaces:** none.
