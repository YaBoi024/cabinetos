# First-time setup lives in the OS, not the installer

- **Decided:** The two setup jobs a console needs before its first start are the image's own, not the installer's. The account `cabinet` (uid and gid 1000, in `wheel`, home `/var/home/cabinet`, password locked) comes from `system_files/usr/lib/sysusers.d/cabinetos.conf`, and its home, a copy of `/etc/skel`, from `tmpfiles.d/cabinetos.conf`. Where updates come from is set at the first start by `cabinetos-update-source.service`: a console with one deployment that does not already follow a signed CabinetOS image is pointed at `ghcr.io/mmagtech/cabinetos:latest`, signed, offline; a console that updated into the image is never moved. The installer ISO only writes the image to the drive, asks which drive and keeps Time & Date.
- **Date:** 2026-11-03
- **Why:** A disk image written to a USB drive (the portable install testers will use) never runs the installer, so setup kept in the installer would need a second copy for it, and the two would drift. In the image, every way onto a drive shares one copy, and an ISO install ends exactly as before. Copying the steps into each way of installing was the other option. A new console goes to `latest` whatever tag its ISO or disk image was built from, as the installer's step did: the builder's own step points it at that tag, and following it would pin a console installed from a version-built ISO to that version for good.
- **Numbers:** none; agreed with MMagTech on 2026-11-02 as step 1 of the portable install plan. #135, "Sign the images", is the signing rule the new console is pointed at.
