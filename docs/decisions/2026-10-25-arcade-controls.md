# Arcade games have a Controls row that moves their buttons

- **Decided:** In FBNeo and MAME 2003-Plus games the pause menu has a Controls row, directly above Exit to Home, when the game names at least one button and a controller is on. It opens in the pause menu's own panel, drawn as the menu's own rows: each of the game's buttons in the core's own words (MAME 2003-Plus's "B1: " taken off) with the button it is on in the controller's own words, "Button 1: A". A on one, then a press, puts it there: on a button another one has, the two swap; on a free one, it moves; so no two share a button and none is lost. A face button (B included), a shoulder or a trigger counts, and the button a game's button is already on leaves it as it was; the stick clicks, Start, Select, the d-pad and the shortcut button do nothing. It plays from the next frame and is kept at once, per game, per kind of controller and per person, over what that controller already does (the fight-stick layout on a stick the console knows, the plain layout on any other pad), in a small file in that person's folder that File access shows, and never sent to RomM. The last row, Reset to default, deletes the file, with no question. With two kinds of controller on, a first row reading "Player 1" or "Player 2" switches between them with Left and Right. Every other system still has no remapping.
- **Date:** 2026-10-25 (settled with MMagTech on 2026-10-24 and 2026-10-25)
- **Why:** An arcade game's buttons have names (Jab Punch, Pedal) and land wherever the core's RetroPad ids fall, which suits few games on a pad and not every game on a fight stick: Gun.Smoke's three fire buttons land on a pad's A, B and X because FBNeo declares them on those ids, wherever a player would rather have them. The objections of 2026-09-26 are met, not overruled: it stays out of every other system and out of Settings, one row and a press with no mapping page; and the four players with no clean owner are answered by keeping it per person and per kind of controller, so player 2's different pad keeps its own. Two pads of one kind share one layout; per pad was offered and not taken. Swap, never overwrite, because a button nobody can press is a game nobody can finish. B counts as a button there, not as a way back, because that screen is for choosing buttons and B is a main one on a pad and on a stick (MMagTech left the choice to the build session, to judge hands-on). The file holds words a person can read and fix, and only what changed. The panel never changes size (MMagTech, 2026-10-25): going more than one menu deep, the pause menu's height and width must never change. And it is drawn as the menu's own rows, not a list of its own, because a different layout in the same panel read as "something off" at the switch (MMagTech at the TV, the same day).
