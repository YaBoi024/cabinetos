# The console's sound has a backup output while the TV's is gone

- **Decided:** The image starts pipewire-pulse at every login of the console's user, so PipeWire's own Dummy Output is there whenever no other output is: the console's sound moves to it while the screen sleeps or the TV is off, and back to the TV when it returns. The image build fails, saying what to redo, if a PipeWire update moves the unit or stops loading that output by default (`build_files/sound-backup-output.sh`).
- **Date:** 2026-10-26 (decided by MMagTech)
- **Why:** SDL 3.4.18, which plays all of the console's own sound, can leave its stream on the TV's dead output when that output disappears and no other exists, and the console stays silent until it is restarted. Upstream has not fixed it (libsdl-org/SDL#16133, milestone 3.6.0, no date). Measured on the A9 with the screen's own sleep and wake: as shipped, silent on the 2nd wake; with pipewire-pulse running and SDL on its usual PipeWire route, 20 of 20 wakes had sound. It is one link in the image and PipeWire's own default; Remote Play already runs pipewire-pulse during every stream, so nothing there changes; and nothing needs undoing when SDL is fixed. It leans on PipeWire's default and the unit's name, so the build checks both rather than letting an update break it silently. Weighed and not taken: the console restarting its own SDL sound when an output appears (new code in the console's sound path); SDL's PulseAudio route for the console (`SDL_AUDIO_DRIVER=pulseaudio`; 20 of 20 too, but games, headphones and Remote Play were never checked on it); waiting for SDL 3.6.0 (no date); patching SDL (a patch to carry on a library the base ships).
- **Numbers:** #228, "Sound can die until a restart"; #591, "Sound comes back after the TV sleeps: a backup output while the TV's is gone".
- **Replaces:** none.
